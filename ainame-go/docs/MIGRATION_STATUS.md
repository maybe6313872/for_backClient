# 迁移状态与兼容性清单

## 当前已实现

- `GET /` -> `{"message":"Hello World"}`
- `GET /hello/{name}` -> `{"message":"Hello {name}"}`
- `GET /health` -> 服务健康状态（Go 新增）
- `POST /name` -> 基础输入校验与单条示例结果；仍是 mock，不是命名算法
- 基础 CORS、JSON 错误响应、handler 单元测试

## 推荐迁移次序

1. 保存并测试现有 API 契约（请求/响应样例、HTTP 状态、字段 snake_case）。
2. 配置与健康检查、统一错误和日志。
3. 单表 CRUD（课程或学校）及 repository 集成测试。
4. 关联数据和事务（学生选课、订单）。
5. 认证与授权；完成后再开放管理接口。
6. 区域 Redis、邮件、Excel 等边缘集成。
7. 用契约测试与真实前端逐路由核验，最后才宣称兼容。

目前 Go 服务器不连接 MySQL/Redis，不进行认证，也没有配置或迁移脚本。不要拿它替换正在使用的 Java 服务。
